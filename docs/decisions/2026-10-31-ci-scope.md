# A PR runs what its paths can break

- Status: accepted
- Date: 2026-10-31

## Context

Every PR ran every test. Of the last 100 merged PRs 9 changed only docs and 27 only the client, its art pipelines and docs, yet
they waited for `Sim.Tests` and `Net.Tests`, most of `dotnet test`'s time. Nothing in the client can change those two: `sim/`
and `net/` reference nothing of `game/`.

## Decision

A `scope` job reads the PR's changed paths, the diff of its merge commit against its base, and `tools/ci-scope.sh` gives its scope:

| Scope | A PR changing only | Runs |
| --- | --- | --- |
| `docs` | `docs/`, `.claude/`, any `README.md`, `CLAUDE.md` | `DocsGuardTests` |
| `client` | those, `game/`, `game.tests/`, `tools/` | `format`, the whole build, `ExportRelease`, `Game.Tests` |
| `all` | anything else | everything |

- A push to `main` is always `all`. `main`'s protection is not strict, so that run is what catches two green PRs breaking each
  other, and a release trusts it.
- Doubt means `all`: a path the script does not know, and no paths at all, which is what a failed `git diff` gives. `format` and
  `build, tests` run unless the scope is exactly `docs`.
- `gate` keeps the name `main`'s protection requires. It is red when a job failed or was cancelled; a job the scope leaves out
  is skipped, and that is fine.
- The scopes follow what the tests read from disk. `Sim.Tests` and `Net.Tests` read only their own fixtures. `Game.Tests` reads
  `game/`, `sim/` and `tools/hero-art/parts.js`, so `tools/` is the client's and not docs; of docs, only `DocsGuardTests` reads
  any. A README outside `docs/` counts as docs; any other `.md` does not, as `SoundTests` reads `game/audio/CREDITS.md`.
- `tools/ci-scope*` is `all`, as a wrong rule could otherwise skip the tests of the PR that wrote it.
- The diff is `--no-renames`, so a file moved out of the sim counts as a change to the sim.
- The two tests of `game/Content/logic/Light.cs` moved from `sim/Tests` to `game.tests`. They test nothing of the sim, and that
  file was all of the client that `sim/` or `net/` compiled. `CiScopeTests` holds both test projects to that, and holds
  `ci.yml`'s filter to the name of `DocsGuardTests`, as a filter that matches nothing passes with nothing run.

## Consequences

- A test that started reading across these lines, `Sim.Tests` reading a file under `game/` or `Game.Tests` a doc, would not run on
  a PR that changes that file. None does today, and `main`'s run would catch it.
- On the runners a PR of docs takes a minute, and a full run 2.5 to 4 minutes, about 7 s of them `scope`. A PR of the client takes
  about 2: its `build, tests` is down to 75–105 s, beside `format`'s 80–120 s, so `format` now counts as much as it does.

## Not done, on purpose

- A workflow-level `paths:` filter: a run it skips leaves the required check pending, and it knows no scopes.
- A third-party filter action: a dependency, for what a dozen lines of bash do.
- Building only the client's projects, or `dotnet format --include game/ game.tests/`: on a desk 3–8 s of a 15–23 s build and 15%
  of `format`, while `format` stays the floor of a client PR's run.
- A project of its own for `DocsGuardTests`, to spare a PR of docs the compile: 9% of PRs.
- A scope for the sim or the net alone: `game.tests` and the game reference both, so little is left to skip.
